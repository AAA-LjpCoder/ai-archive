## 开头钩子（三选一）

1. **场景**：资料散在手机相册 / 聊天文件 / 网盘，想找一句话得翻半天 →「能不能直接问它？」

3. **反差**：一个自娱自乐的小工具，却把「评估」当正经事做了。

## 主体结构

1. **成品长什么样**（配 3 张截图：首页 / 问答 / 引用）
2. **技术选型与取舍**
   - 后端 FastAPI + PostgreSQL/pgvector（不上向量库 SaaS，省事省钱）
   - 前端原生小程序（不套框架，包体小、可控）
   - 模型分层：生成用 DeepSeek，向量/精排/视觉用智谱
3. **核心链路拆解**
   - 上传 → 解析（多格式）→ **结构感知分块**（标题路径作上下文）
   - 向量化 → **混合检索**：全库 BM25 ∪ 向量 → RRF → 精排 → 去冗余
   - **SSE 流式** + 引用溯源，正文 Markdown 渲染
4. **「效果」如何量化**：自建 34 题 golden set + Recall@K / MRR → R@6 91.2%（贴结果表；详见仓库 `docs/eval`）
5. **踩过的坑（挑 3~5 个真实的）**
   - pgvector HNSW **2000 维上限** → 嵌入模型被迫选 1024 维
   - SSE **半包丢帧** → 行缓冲 + 流式 UTF-8 解码
   - OCR：某模型**输出乱码 / 空响应**，长图**输出被截断** → 按截断自适应切分再合并
   - 微信 `uploadFile` 的 `file.filename` 是**临时路径名** → 用 formData 传原始名
   - 明文 `http://IP` 被微信拦截、登录态过期卡死 → 上 HTTPS + token 自愈
   - `create_all` **只建表不加列** → 迁移要写幂等 `ALTER TABLE ... IF NOT EXISTS`
6. **上线与合规**：域名 → HTTPS → 小程序备案 → 隐私指引 → 提审发布
7. **复盘**：如果重来会怎么改；给想做同类项目的人的建议
8. **结尾**：GitHub 仓库地址 + 小程序码
