## 1. 产品概述

### 1.1 一句话定位
**把自己的文档变成 24 小时在线的 AI 助手：上传即问，回答必带出处。**

### 1.2 核心价值
| 用户痛点 | 本产品解法 |
|---------|-----------|
| 文档太多找不到内容 | 自然语言提问，秒级定位 |
| 读长文档费时间 | 基于原文的精准摘要/要点提取 |
| 通用 AI 回答不专业、不基于你的资料 | 只基于用户上传的文档回答，带引用溯源 |
| 信息零散不成体系 | 私有知识库沉淀，跨文档串联问答 |

### 1.3 设计原则
1. **私人数据是底线**：多租户隔离，A 用户永远查不到 B 用户的文档
2. **回答可溯源**：每条回答必须能对应到原文片段，宁缺毋假
3. **渐进式升级**：自用版与大众版共用 80% 代码，只差用户系统与额度运营
4. **成本可控**：额度机制 + 广告解锁，防止算力被薅

## 2. 市场与背景

- 2026 年 RAG 已是企业知识管理标配，但 C 端"个人文档问答"仍无强对标产品
- 用户上传文档 = 全行业通用场景（学生/打工人/创作者/律师/医生…）
- 与通用 AI 的差异点：**基于私有资料 + 引用溯源**，通用 AI 无法替代
- 广告变现可行性：工具类目 + 高频使用 + 激励视频点位多

## 4. 功能需求（MVP 详细）

### F1 文档管理（核心）

#### F1.1 上传
| 项 | 说明 |
|----|------|
| 支持格式 | v1：`txt` / `md` / `pdf`；v2：`docx` / `xlsx` / 图片 OCR |
| 大小限制 | 单文件 ≤ 20MB；单用户总容量 ≤ 100MB（广告扩额见 F4） |
| 数量限制 | 免费 10 个文档/用户（激励视频 +1 个/次，单日上限 +3） |
| 方式 | 微信会话选择文件（`wx.chooseMessageFile`），后续可加拍照/相册 |
| 上传即走 | 上传后后台异步处理，用户可离开，处理完通知 |

#### F1.2 解析与处理（异步任务）
| 步骤 | 说明 | 状态机 |
|------|------|--------|
| 1 接收 | 文件入队，状态 `pending` | pending |
| 2 解析 | 按格式提取纯文本（PDF→pdfplumber；txt/md→直接读取） | processing |
| 3 分块 | 语义分块（见 §8.3） | processing |
| 4 向量化 | 每块生成 embedding（BGE，见 §8.2） | processing |
| 5 入库 | 写入向量库 + 原文存储 | ready / failed |
| 失败处理 | 解析失败（加密 PDF/损坏文件）明确提示原因，可重试/删除 | failed → 可重试 |

#### F1.3 文档列表与操作
- 展示：文件名、类型图标、大小、处理状态（处理中显示进度）、分块数、上传时间
- 操作：重命名、删除（级联删除向量与分块）、查看详情（解析预览 + 分块统计）
- 空态：引导页（"上传你的第一份文档"）

### F2 AI 问答（核心）

#### F2.1 问答模式
| 模式 | 说明 |
|------|------|
| 全局问答 | 检索用户全部文档（默认） |
| 单文档问答 | 在文档详情页"针对此文档提问"（限定检索范围） |
| 仅检索模式 | 不做 LLM 生成，直接返回命中的原文片段列表（省 token，查资料用，额度消耗减半） |

#### F2.2 回答质量要求
- **只基于用户文档回答**；文档中无答案时明确说"你的文档中没有相关内容"，禁止编造
- **引用溯源**：回答中的关键句带角标 `[1] [2]`，对应下方引用卡片（文档名 + 原文片段 + 页码/位置），点击可查看
- **连续对话**：同一会话内支持多轮追问（携带上下文，见 §8.5）
- 单次回答最长约 800 字（防止无限生成烧钱）

#### F2.3 流式输出（★ 强制要求，已确认）
- **必须实现**打字机效果（SSE 流式），禁止"转圈等完整结果"
- 验收指标：首 token ≤ 3s；输出速率 ≥ 20 字/s
- 技术：FastAPI `StreamingResponse` SSE → 前端逐块渲染（见 §8.4）

#### F2.4 会话管理
- 自动生成会话标题（基于首问）
- 会话列表：历史会话可重进、可删除
- 每会话对话轮数上限：免费 20 轮/天（见 F4）

### F3 用户系统（v1 简化版，为 V2 铺路）
| 项 | 说明 |
|----|------|
| 登录 | 微信静默登录（`wx.login` + openid），自用阶段免授权弹窗 |
| 多租户隔离 | **所有数据查询强制带 user_id 条件**（后端白名单校验，见 §8.6） |
| 多账号 | 同 openid 单用户 |

### F4 额度与广告（v1 植入机制，v2 正式运营）
| 资源 | 免费额度 | 广告解锁 |
|------|---------|---------|
| 文档数量 | 10 个/用户 | 激励视频 +1 个（单日上限 +3） |
| 总容量 | 100MB | — |
| 问答轮数 | 20 轮/天 | 激励视频 +10 轮 |
| 单文档问答 | 不限 | — |
| 广告形式 | — | 激励视频（额度不足时前置点位；处理完成时后置福利位） |
| 流量主 | 累计 UV≥1000 开通，Banner 展示于文档库/会话列表底部 | — |

### F5 历史记录
- 会话按时间倒序，显示标题、最后消息摘要、时间
- 支持搜索会话（v2）

### F6 设置与帮助
- 额度说明页（还剩多少、怎么获取）
- 隐私说明（文档仅本人可见、数据加密传输、可一键删除所有数据）
- 反馈入口（自用阶段 = 微信直聊）

## 5. 非功能需求

| 维度 | 要求 |
|------|------|
| 性能 | 上传 10MB PDF → 处理完成 ≤ 60s；问答首 token ≤ 3s；流式输出 ≥ 20 字/s |
| 稳定性 | 异步任务可重试，断点恢复（任务表 + 状态机） |
| 安全 | 全链路 HTTPS；服务端鉴权；密钥不出前端 |
| 数据 | 用户删除文档 = 物理删除向量+分块+原文；提供"清空全部数据" |
| 成本 | 单用户月成本 ≤ ¥1（见 §8.7 成本模型） |
| 合规 | AI 回答标注"AI 生成"；上传内容接微信内容安全 API 审核（见 §9） |

### 6.3 核心流程
```
上传：文档库 → 上传 → 选文件 → 校验(格式/大小/额度) → 上传 → 状态流转(pending→processing→ready)
     → 完成通知 → 文档列表可提问
问答：问答Tab → 输入问题 → (额度校验) → SSE 流式回答 + 引用卡片 → 可追问 → 结束/退出
解锁：额度不足 → 弹窗"看广告 +10 轮" → 激励视频 → 额度到账 → 继续
```

### 7.3 索引
- chunks：`(user_id, doc_id)` 组合索引；`embedding` 向量索引（HNSW, m=16, ef_construction=64）
- messages：`(conversation_id, created_at)`
- 所有查询强制 `user_id` 前缀，杜绝跨租户

## 8. 技术架构方案（已定：自建 FastAPI + 轻量云服务器）

### 8.0 技术栈一览表（一页看完）

| 层次 | 技术选型 | 说明/备注 |
|------|---------|----------|
| 前端 | 微信原生小程序（WXML/WXSS/JS） | 页面：chat / docs / mine；Taro 仅备选 |
| 后端 | FastAPI（Python 3.11+） | REST + SSE 流式；复用 ETG Copilot 经验 |
| 异步任务 | asyncio 后台任务 / Celery | 解析→分块→向量化 异步处理 |
| 数据库 | PostgreSQL 16 + pgvector | 业务数据 + 向量同库 |
| 向量索引 | HNSW（m=16, ef_construction=64） | 1024 维向量检索 |
| Embedding | BGE-M3（1024 维）：自部署微服务 或 硅基流动 API | MVP 先用 API 零运维，后切自部署 |
| 混合检索 | BM25 + 向量 + MMR 重排 | 复用 aicoding 经验（召回 92.72%） |
| LLM | DeepSeek API（主）／ 硅基流动 Qwen（备） | 成本敏感，涨价可切换 |
| 文档解析 | pdfplumber / python-docx / 内置 txt·md 解析 | 纯 Python 免费；OCR 用 PaddleOCR（v2） |
| 文件存储 | v1 本地磁盘 → 上架后阿里云 OSS | 平滑迁移 |
| 流式输出 | FastAPI StreamingResponse（SSE）★ | 强制要求，见 §4.2.3 |
| 部署 | Docker Compose @ 轻量云 Ubuntu 22.04（2C2G） | 一揽子：API + PG + 可选 BGE |
| 域名 | M1 调试期不需要；上架前 ICP 备案 + HTTPS | 个人可备案，周期 2-4 周 |
| 监控 | 日志 + 用量统计；告警 v1 后补 | 成本监控防失控 |

### 8.2 关键选型（已确认）

| 混合检索 | BM25 + 向量 + MMR 重排 | 复用 aicoding 混合检索经验（召回率 92.72%） |

| 文件存储 | v1 本地磁盘；上架后阿里云 OSS | 平滑迁移 |
| 流式 | FastAPI `StreamingResponse` SSE（★必须） | 前端逐块渲染 |

### 8.3 分块策略（中文场景）
- **层级分块**：按 Markdown/PDF 标题切大块（≤2000 字），大块内按段落/句群切小块（400~600 字，重叠 80 字）
- 元信息：保留来源页码 + 章节标题，问答时随片段返回（引用溯源基础）
- 表格/代码块：单独成块，不硬切

### 8.4 RAG 问答流程（单轮）
```
1 用户提问 → 2 额度校验(服务端) → 3 问题向量化
→ 4 向量检索 top20 (限定 user_id + 可选 doc_id)
→ 5 BM25 检索 top20 → 6 混合融合(RRF) → 7 MMR 重排 top6
→ 8 组装 Prompt(带 [n] 引用标记) → 9 LLM SSE 流式生成★
→ 10 前端渲染回答 + 引用卡片 → 11 会话/用量落库
```

### 8.5 Prompt 设计草案
```
SYSTEM:
你是一个严谨的私人知识库助手。你只能基于用户提供的文档内容回答。
规则：
1. 回答必须来源于文档，关键结论后标注引用 [n]，n 对应提供的片段编号
2. 文档中没有答案时，明确回答"你的文档中没有相关内容"，不要编造
3. 使用中文回答，语言简洁、条理清晰
4. 涉及多个文档时，优先综合，标注各出处

USER:
【检索片段】
[1] 《ETG产品需求文档_精读笔记.md》第3页: ...
[2] 《口味测试分析.md》第12页: ...
【历史对话】(多轮时携带)
【当前问题】
xxx
```

### 8.6 多租户安全设计
- 所有 SQL 强制 `WHERE user_id = ?`，禁止裸查询
- 文档/会话/消息读写统一走服务层鉴权函数
- 上传文件名校验 + 内容安全审核（微信内容安全 API `msgSecCheck`）
- 额度在服务端校验与扣减（前端仅展示，防绕过）

## 11. 验收标准（MVP 关键指标）

- [ ] 上传 10MB PDF，60 秒内变 ready
- [ ] 加密/损坏 PDF 明确报错可重试
- [ ] 全局问答：基于 3 份真实文档回答 10 个问题，≥8 个有正确引用，0 编造
- [ ] 单文档问答只检索该文档
- [ ] **流式输出达标：首 token ≤3s，速率 ≥20 字/s**（★已确认必做）
- [ ] 额度不足弹广告解锁，服务端同步扣减（抓包伪造请求无效）
- [ ] 两账号数据完全隔离（含向量检索）
- [ ] 删除文档后向量/分块/原文全部消失

## 12. 附录

### A. 引用卡片交互
回答渲染时，`[n]` 角标可点击 → 底部弹出卡片：文档名、原文片段（高亮命中词）、页码 → 点击跳转文档详情对应位置（v2 支持定位）。

### B. 仅检索模式
输入问题 → 直接返回 top5 原文片段列表（带文档名+页码），不做 LLM 生成。适用：查原文、省额度。额度消耗减半。

### C. 广告点位清单
| 点位 | 触发 | 形式 |
|------|------|------|
| 额度不足 | 问答/上传被拦截时 | 激励视频（+10 轮 / +1 文档） |
| 上传完成 | 处理成功后 | 激励视频（可选观看，福利位） |
| 会话列表底部 | 常驻 | Banner |
| 文档库底部 | 常驻 | Banner |

### D. 平滑升级路线（自用 → 大众）
```
M1 单用户自用(openid 固定)
 → M2 开放登录，每个 openid 独立数据(代码已隔离)
 → M3 额度+广告(已有机制)
 → M4 上架 + 流量主 + 内容审核强化
 → V2 多知识库/会员/分享协作
```
核心结论：**自用版就是大众版的第一个真实用户，架构不推倒。**
